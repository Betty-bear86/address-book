# 编码规范

本文件是通讯录管理系统（Address Book）的代码规范，提交代码前请对照检查。
规范参考 [PEP 8](https://peps.python.org/pep-0008/)、[Google Python Style Guide](https://google.github.io/styleguide/pyguide.html) 与 [Airbnb JavaScript Style Guide](https://github.com/airbnb/javascript) 的常用约定，并针对本项目做了裁剪。

## 1. 通用约定

- 编码统一使用 **UTF-8**，换行使用 **LF**；文件末尾保留一个空行。
- 缩进：Python / JavaScript / CSS 均为 **4 空格**（CSS 允许 2 空格，但同一文件内保持一致）。
- 单行不超过 **100 字符**，超出时换行并对齐参数。
- 不在代码中提交调试输出（`print` / `console.log`）、注释掉的废弃代码与本地绝对路径。
- 不提交 `data/*.db`、日志、虚拟环境与个人 IDE 配置（见 `.gitignore`）。

## 2. Python 规范

### 2.1 命名

| 对象 | 风格 | 示例 |
| --- | --- | --- |
| 模块 / 包 | `snake_case` | `excel_io.py`、`validation.py` |
| 函数 / 变量 | `snake_case` | `normalize_contact`、`contact_id` |
| 常量 | `UPPER_SNAKE_CASE` | `METHOD_TYPES`、`MAX_NAME` |
| 类 | `PascalCase` | `ContactStore`、`ValidationError` |
| 私有成员 | 单下划线前缀 | `_serialize`、`_insert` |

### 2.2 函数与类型

- 所有公开函数写简短 docstring，说明**做什么、参数含义、异常行为**，而不是逐行解释实现。
- 使用类型注解（`dict[str, Any]`、`str | None`），文件头开启 `from __future__ import annotations`。
- 单个函数不超过 50 行；超过时拆分为职责单一的小函数（如 `_normalize_method` / `normalize_methods`）。
- 模块级共享常量集中在文件顶部，用元组而不是列表，避免被意外修改。

### 2.3 异常与校验

- 业务校验失败抛出 `ValidationError(message, field)`，由 API 层统一转换为 `400` 与 JSON 错误体，**不在视图函数里写大段 try/except**。
- 数据库连接统一通过 `Database.cursor()` 上下文管理器获取，确保 `commit` / `rollback` / `close` 成对出现。
- 禁止空 `except:`；无法处理时向上抛出，或注释说明为何忽略。

### 2.4 数据库

- 所有 SQL 使用参数化占位符 `?`，**禁止字符串拼接用户输入**。
- `LIKE` 查询对 `%`、`_`、`\` 转义并显式声明 `ESCAPE '\'`。
- 删除联系人依赖外键 `ON DELETE CASCADE` 级联清理联系方式，不在应用层重复删除。
- 建表语句使用 `CREATE TABLE IF NOT EXISTS`，保证可重复初始化。

### 2.5 安全

- 上传文件校验扩展名（`.xlsx` / `.xlsm`）与大小（10 MB），并用 `openpyxl` 解析失败兜底提示。
- 后端始终以 `normalize_contact` 的结果入库，不信任前端传来的字段与类型。

## 3. JavaScript 规范

- 使用 ES6+，整个文件包裹在 `(() => { 'use strict'; ... })()` 中，避免污染全局。
- 变量声明使用 `const` / `let`，不使用 `var`；禁止隐式全局变量。
- 命名：变量与函数 `camelCase`，常量 `UPPER_SNAKE_CASE`，DOM 引用统一放在 `els` 对象中。
- 事件绑定使用**事件委托**（列表、抽屉、快捷卡片各绑定一次），避免为每一行重复绑定。
- 所有插入 `innerHTML` 的用户数据必须经过 `escapeHtml()`；高亮搜索关键词使用 `highlight()`，禁止直接拼接原始文本。
- 网络请求统一走 `api()` / `downloadFile()`，错误统一 `toast()` 提示，不在业务逻辑里散落 `try/catch` 提示文案。
- 渲染函数保持**纯函数**：只根据 `state` 生成 HTML，不发起请求、不修改 `state`。

## 4. CSS 规范

- 颜色、圆角、阴影、字体统一使用 `:root` 中的 CSS 变量，禁止在组件里写死色值（图标渐变等特例除外）。
- 类名使用简短的小写语义化命名（`contact-view`、`drawer-body`、`method-row`），状态类使用 `is-` / `on` / `active` 前缀或后缀。
- 布局优先使用 Grid / Flex，避免 `float` 与绝对定位堆叠。
- 响应式断点统一为 `1180px / 980px / 720px`，新增组件必须同时在三个断点下自测。
- 支持 `prefers-reduced-motion`，动画时长不超过 300ms。

## 5. Git 规范

### 5.1 提交信息

采用 `type(scope): subject` 形式，其中 `type` 取值：

| type | 含义 |
| --- | --- |
| feat | 新功能 |
| fix | 缺陷修复 |
| refactor | 重构（不改变行为） |
| style | 样式 / 格式调整 |
| test | 测试相关 |
| docs | 文档 |
| chore | 构建、依赖、配置 |

示例：`feat(excel): 支持导入时按姓名与联系方式合并去重`。

### 5.2 提交要求

- 一次提交只做一件事，提交前确保 `python -m unittest discover -s tests` 通过。
- 提交信息使用中文或英文均可，但同一仓库保持一致；本仓库使用中文描述。
- 不提交未完成的调试代码；临时文件放 `.tools/` 并加入 `.gitignore`。

## 6. 提交前检查清单

- [ ] 新增功能有对应的接口 / 页面自测，必要时补充单元测试。
- [ ] 中文文案无错别字，数字与单位之间有空格。
- [ ] 没有把 `data/` 下的数据库文件、截图临时文件提交进仓库。
- [ ] 新增的 CSS 变量已放在 `:root`，新增的 API 已写入 README 的接口表。
- [ ] 浏览器控制台无报错，页面在 1600px 与 430px 宽度下均可用。
